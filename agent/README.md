# 🕸️ סוכן רשת

סוכן שסורק אתרים, מסנן את מה שרלוונטי ומדווח — **בלי לכתוב קוד לכל אתר**.
משימת מעקב חדשה היא קובץ JSON: מקורות, טקסונומיה, שערים. הקוד לא משתנה.

```bash
node agent/run.js --list                        # אילו משימות מוגדרות
node agent/run.js --watch=<id> --probe          # מי נענה ומי חוסם. לא שומר.
node agent/run.js --watch=<id> --audit          # איפה נפל כל פריט. לא שומר.
node agent/run.js --watch=<id> --dry-run        # סריקה מלאה, הדפסה בלבד
node agent/run.js --watch=<id>                  # סריקה + שמירה
node agent/run.js --watch=<id> --source=<id>    # מקור בודד
npm run test:agent                              # בדיקות, בלי רשת
```

בסביבת פיתוח בלי גישת רשת החוצה מריצים את אותן פקודות מ-**Actions → `agent`**.

---

## מאיפה זה הגיע

הליבה כאן לא נכתבה מאפס — היא **הופקה מראדאר המכרזים** שרץ במאגר הזה כל יום
ומכסה 65 מקורות. הקוד שסורק אתר, מגלה בעצמו את עמוד הרשימה, מתאים מונחים
בעברית ומנהל היסטוריה היה תמיד גנרי; הוא פשוט ישב בתוך סקריפט אחד שידע רק
מכרזים. ההפקה הוציאה אותו החוצה, והראדאר צורך אותו משם — **מימוש אחד, לא שניים**.

הרווח אינו ארגוני. כל כלל בליבה נקנה בתקלה אמיתית באתר אמיתי, והם מתועדים
במקום שבו הם חיים ([`tenders/README.md`](../tenders/README.md) מתעד את המדידות
עצמן). משימה חדשה מקבלת אותם בחינם, במקום לגלות אותם מחדש.

## איך משימה עובדת

```
מקורות → קציר → שער → סיווג → תאריכים → מיזוג עם ההיסטוריה → דיווח
```

**1. קציר.** לכל מקור יש `kind`:

| `kind` | מה הוא עושה |
| --- | --- |
| `html` | קוצר קישורים מדף רשימה שכתובתו ידועה |
| `discover` | נכנס לדף הבית, **מאתר בעצמו** את עמוד הרשימה, וקוצר משם |
| `rss` | קורא פיד RSS/Atom |
| `json` | שולף רשומות מ-API, לפי מפת שדות בתצורה |

הקציר גנרי בכוונה — הוא לא מכיר את מבנה ה-DOM של אף אתר, אלא אוסף כותרות
קישורים ואת חלון הטקסט סביבן. לכן הוא לא נשבר בכל שינוי עיצוב, וזו הסיבה
שאותו קוד עובד על עשרות אתרים שאיש לא כתב עבורם מתאם.

**2. שער.** שואל "האם זה בכלל מהסוג שחיפשנו", לפני שאלת הנושא. משימת חדשות לא
צריכה שער (`phrases: []`) — הטקסונומיה לבדה מסננת. משימת מכרזים כן: בלעדיו כל
קישור באתר נכנס.

**3. סיווג.** כל כותרת מנוקדת מול הטקסונומיה. ההתאמה מודעת לעברית: תחיליות
(ו/ה/ב/ל/מ/ש/כ) וסיומות נטייה מזוהות, כך ש"והתקשורת" ו"תקשורתיים" נתפסים כמו
"תקשורת". ראשי תיבות באנגלית נבדקים כמילה שלמה וברגישות לאותיות גדולות, כדי
ש-`IT` לא ייתפס מתוך המילה `it`. **מילות שלילה מקזזות את הניקוד של כל נושא**,
ולכן "מכרז לקלינאי תקשורת" אינו נכנס לנושא תקשורת אף שהמילה מופיעה בו.

**4. תאריכים.** נחלצים לפי ביטוי הרמז שלפניהם ("מועד אחרון", "פורסם ב"), ולא
לפי התאריך הראשון בשורה — אחרת תאריך פרסום ומועד הגשה מתחלפים.

**5. מיזוג.** `firstSeen` המקורי נשמר, כך שהסימון "חדש" אמיתי. רשומה יורדת
כשהמועד חלף, כשהיא מתיישנת, או כשהתצורה כבר לא מקבלת אותה.

## שבעה כללים שנקנו בתקלות

הליבה מקודדת את אלה. הם לא הערות סגנון — כל אחד נמדד באתר אמיתי.

**1. הסיווג מתעלם מחלון ההקשר.** בדף רשימה צפוף, חלון ההקשר של פריט אחד בולע
את שכניו. סיווג עליו נותן לכל פריט את המונחים של הפריט שאחריו: מכרז גינון מקבל
נושא "תקשורת" מהמכרז שמעליו, ומכרז שנחסם במילות שלילה ניצל מהן בזכות ניקוד
שכניו. הסיווג רץ על הכותרת והתקציר שהמפרסם כתב בלבד; ההקשר משמש לתאריכים.

**2. כתובת שנכשלת אינה מפילה מקור שלם.** היא נרשמת כאזהרה והסריקה ממשיכה;
המקור נכשל רק אם כל כתובותיו נכשלו. בלי זה מקור עם חמש כתובות שאחת מהן זזה
נעלם מהתוצאות כליל.

**3. הדירוג בגילוי הוא סדר ניסיון, לא סינון.** כשהעמוד המועדף אינו נטען עוברים
לבא בתור. סינון מוחלט הפך מקורות לכושלים כשהמועמד המועדף החזיר 404.

**4. ערך ריק אינו דורס ערך שמור.** דף רשימה בלי מועד מחזיר `deadlineAt: ''`,
ומיזוג נאיבי (`{...prev, ...rec}`) מוחק בדיוק את המועד שנשלף בעמל מדף הפריט.
מה שהפך את זה לקבוע: הדגל "כבר בדקנו" כן שרד, ולכן אותן רשומות לא נבדקו שוב
**לעולם**. ערך חדש שאינו ריק עדיין גובר, כדי שהארכת מועד תעדכן.

**5. שגיאת 4xx אינה מנוסה שוב.** היא קבועה. בסריקה של עשרות אתרים, ניסיונות
חוזרים על כתובות מתות הופכים ריצה של דקות לריצה של שעה. `429` הוא היוצא מן הכלל.

**6. 403 של היום אינו 403 קבוע.** מקור שחוסם תמיד צריך לעבור לבדיקה ידנית;
מקור שעבד אתמול ונכשל היום הוא כמעט תמיד הגבלת קצב. בסריקה אחת החזירו 17
רשויות 403 אחרי שעבדו ארבעים דקות קודם — בלי ההבחנה הן היו יורדות לתמיד.
למחרת, בלי שום שינוי בקוד, כולן נסרקו. לכן כל מקור נושא `lastOkAt`,
`failingSince` ו-`likelyTransient`.

**7. כל נשירה מסווגת לסיבה.** הסוכן מוצא הרבה יותר ממה שהוא שומר, ובלי פירוט
אי אפשר לדעת אם הסינון עובד או בולע פרסומים אמיתיים. ביקורת המשפך על 30 רשויות
מצאה בדיוק כך שמגזר שלם נופל על **תאריכים** ולא על תוכן — מסקנה שאי אפשר להגיע
אליה מספירת התוצאות.

## להוסיף משימה

```bash
cp agent/watches/example.watch.json agent/watches/my-watch.watch.json
```

התבנית מסבירה כל שדה. אחרי העריכה, **בסדר הזה**:

```bash
node agent/run.js --watch=my-watch --probe     # 1. מי בכלל נענה
node agent/run.js --watch=my-watch --audit     # 2. איפה נופל כל פריט
node agent/run.js --watch=my-watch --dry-run   # 3. מה ייכנס בפועל
```

ורק אז `"enabled": true` והוספת תזמון ל-[`.github/workflows/agent.yml`](../.github/workflows/agent.yml).

### מדדו לפני שאתם מסיקים

**כתובת משוערת שלא נענתה אינה "אתר חוסם".** היא לרוב כתובת שגויה, ושתי
המסקנות נראות זהות בלוג. במאגר הזה בדיוק הבלבול הזה סיווג שש רשויות
כ"החיבור נכשל" כשהדומיין פשוט היה שגוי — `carmiel` במקום `karmiel`,
`sderot` במקום `sederot`. מהכיוון ההפוך: `meitar.co.il` נענה יפה והוביל
ל**משרד עורכי דין**, לא למועצה. אתר שנענה אינו הוכחה שהגעת לגוף הנכון.

`--probe` הוא מה שמחליף ניחוש במדידה.

### מה הסוכן לא יעשה

- **לא יעקוף הגנות בוט.** אתר שמחזיר 403 באופן קבוע עובר לבדיקה ידנית. הסוכן
  מזדהה ב-User-Agent שמפנה למאגר, כדי שמפעיל אתר יוכל לדעת מי זה.
- **לא יריץ JavaScript.** אתר שבונה את הרשימה בדפדפן יחזיר 0 תוצאות, וזה
  ידווח במפורש כ-0 ולא כהצלחה שקטה.
- **לא ימהר.** יש השהיה בין בקשות לאותו מקור (`politeDelayMs`), ומקבילות
  היא בין מקורות שונים בלבד.

## למה פרופיל המכרזים מנוטרל

`tenders.watch.json` הוא תצורת הראדאר בפורמט הסוכן, ו-`enabled: false` בכוונה.
**הראדאר עצמו ממשיך לרוץ מ-`.github/scripts/tenders-fetch.js`**, משתי סיבות:

1. שתי מערכות שסורקות את אותם 65 אתרים מכפילות את התעבורה אליהם, ושוברות את
   כלל הנימוס שהראדאר מקפיד עליו.
2. הראדאר עושה דברים שהסוכן הגנרי אינו עושה — העשרת מועדים מדף המכרז עצמו,
   סיווג סוג פרסום (פטור / כוונת התקשרות / מכרז כוח אדם), סינון לפי הגוף
   המפרסם, וסקירת AI לכמעט־התאמות. הסוכן הוא הליבה המשותפת, לא תחליף.

מה כן עושים איתו: `--audit` מריץ את המשפך הגנרי על קורפוס מקורות שנמדד ומוכר,
וכך מודדים שינוי בליבה מול תוצאה ידועה מראש.

## בדיקות

```bash
npm run test:agent      # ליבת הסוכן בלבד
npm test                # הכול: הסוכן + הראדאר
```

הבדיקות מזריקות לקוח רשת מזויף ולכן **רצות בלי רשת**, אבל דרך אותו מסלול קוד
בדיוק שרץ בייצור: אותם מתאמים, אותם שערים, אותו מיזוג היסטוריה. הפיקסטורים
ב-`agent/test/fixtures/` הם דף בית ודף מכרזים של רשות מקומית מומצאת, עם בדיוק
המלכודות שנמצאו באתרים אמיתיים — ארכיון, דרושים, פרוטוקולים, ועדת מכרזים,
"לחצו כאן", וקלינאות תקשורת.

**בדיקות הראדאר הן חלק מהבטיחות של הסוכן.** הליבה הופקה מהראדאר בלי שינוי
התנהגות, ו-115 בדיקות הראדאר רצות מול הקוד המשותף. שינוי בליבה שישבור את
הראדאר ייתפס מיד.
